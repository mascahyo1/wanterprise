================================================================================
 TABLE: spatie_permission_tables (roles, permissions, etc.)
 Deskripsi : Struktur tabel untuk RBAC menggunakan package Spatie Laravel-Permission
================================================================================

 Secara default, package Spatie akan di-publish dan dimodifikasi agar mendukung arsitektur multi-tenant (SaaS) kita, serta menggunakan UUIDv7.

 1. TABLE: permissions
 ─────────────────────────────────────────────────────────────────────────────
 id                  UUIDv7              PK
 name                string(255)         Nama permission (contoh: 'messages.send')
 description         text null           Penjelasan detail (contoh: 'Akses untuk mengirim atau membalas pesan')
 scope               enum                'saas' | 'company' (Untuk membedakan ini fitur global SaaS atau fitur internal perusahaan)
 order_column        integer             Urutan tampilan di UI (agar rapi saat di-render)
 guard_name          string(255)         Default: 'web'
 created_at          timestamp
 updated_at          timestamp

 2. TABLE: roles
 ─────────────────────────────────────────────────────────────────────────────
 id                  UUIDv7              PK
 company_id          UUIDv7 null         FK → companies.id
 name                string(255)         Nama role (contoh: 'Super Admin', 'Operator')
 description         text null           Penjelasan scope pekerjaan (contoh: 'Hanya bisa membalas chat')
 scope               enum                'saas' | 'company'
 order_column        integer             Urutan tampilan di UI
 guard_name          string(255)         Default: 'web'
 created_at          timestamp
 updated_at          timestamp

 *Catatan Aturan Bisnis:
 - Jika `scope` = 'saas', maka `company_id` WAJIB `null`.
 - Jika `scope` = 'company', maka `company_id` TIDAK BOLEH `null` (harus menunjuk ke ID perusahaan tertentu).
 - Tidak ada "Global Company Role" yang `null`. Setiap kali ada pendaftaran perusahaan (tenant) baru, role default (seperti 'Company Admin' atau 'Operator') harus di-insert langsung ke tabel ini dengan `company_id` milik mereka.

 3. TABLE: role_has_permissions (Pivot)
 ─────────────────────────────────────────────────────────────────────────────
 permission_id       UUIDv7              FK → permissions.id
 role_id             UUIDv7              FK → roles.id

 4. TABLE: model_has_permissions (Pivot)
 ─────────────────────────────────────────────────────────────────────────────
 permission_id       UUIDv7              FK → permissions.id
 model_type          string(255)         Default: 'App\Models\User'
 model_id            UUIDv7              FK → users.id
 team_id             UUIDv7              FK → companies.id (Digunakan Spatie untuk memisahkan scope per workspace)

 5. TABLE: model_has_roles (Pivot)
 ─────────────────────────────────────────────────────────────────────────────
 role_id             UUIDv7              FK → roles.id
 model_type          string(255)         Default: 'App\Models\User'
 model_id            UUIDv7              FK → users.id
 team_id             UUIDv7              FK → companies.id (Sangat krusial untuk arsitektur Many-to-Many Workspace)

 ─────────────────────────────────────────────────────────────────────────────
 INDEXES & RELATIONS
 ─────────────────────────────────────────────────────────────────────────────
 - Pengecekan default bawaan Spatie (membuat unique constraint `name` + `guard_name`).
 - Pada tabel `roles`, unique constraint menjadi `name` + `guard_name` + `company_id`.
 - Relasi morphTo() dipakai Spatie secara otomatis (`model_type` & `model_id`).
 - FITUR TEAMS: Spatie akan di-configure dengan `'teams' => true` dan `'team_foreign_key' => 'team_id'`. Kita menggunakan kolom `team_id` yang sebenarnya merujuk ke tabel `companies.id`. Hal ini memungkinkan User A menjadi 'Company Admin' di team/company X, tapi hanya menjadi 'Operator' di team/company Y.
