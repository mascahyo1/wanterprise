================================================================================
 TABLE: saas_users
 Deskripsi : Pengguna internal penyedia platform SaaS (Super Admin, Tim Support, Finance SaaS). 
             Secara fisik dipisahkan dari pengguna tenant (`users`) untuk keamanan dan kebersihan arsitektur.
================================================================================

 1. COLUMNS
 ─────────────────────────────────────────────────────────────────────────────
 id                  UUIDv7              PK
 name                string(255)         Nama lengkap
 email               string(255)         Email login (unique)
 password            string(255)         Bcrypt hashed
 avatar              string(255) null    Path avatar/foto profil
 is_active           boolean             Default: true
 last_login_at       timestamp null      Waktu login terakhir
 created_at          timestamp
 updated_at          timestamp
 deleted_at          timestamp null      Soft delete

 2. INDEXES
 ─────────────────────────────────────────────────────────────────────────────
 • UNIQUE  email
 • INDEX   is_active

 3. RELATIONS
 ─────────────────────────────────────────────────────────────────────────────
 • morphMany      (Spatie) roles       (Guard: 'saas')
 • morphMany      (Spatie) permissions (Guard: 'saas')

 4. NOTES
 ─────────────────────────────────────────────────────────────────────────────
 • Pemisahan fisik: Tim internal Wanterprise (pengelola SaaS) akan menggunakan guard authentication khusus (misal: `auth:saas`).
 • Bebas dari logika tenant: Karena dipisah di tabel ini, kita tidak perlu mengakali `company_id = null` pada tabel `users`.
 • Memiliki Panel Login sendiri: Misalnya di `wanterprise.com/admin/login`, terpisah dari halaman login customer/klien.
 • DYNAMIC RBAC (NO HARDCODE): Sama seperti tenant, pengguna SaaS TIDAK DI-HARDCODE sebagai "Super Admin". Mereka menggunakan sistem Roles & Permissions yang dinamis (via Spatie dengan guard `saas`). Artinya, tim manajemen SaaS bisa membuat *role* kustom tak terbatas untuk staf internal mereka sendiri (contoh: "SaaS Finance", "SaaS L1 Support", "SaaS Security") dengan racikan permission granular (contoh: `saas_billing.view`, `saas_companies.suspend`). Semua akses wajib divalidasi lewat permission.
